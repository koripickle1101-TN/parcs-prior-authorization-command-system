# Documentation Readiness Checklist

## PARCS 2.0

**Created by Kori Pickle**

## Purpose

This checklist prevents authorization cases from moving forward before clinical and payer-required documentation is ready.

## Readiness Review

| Requirement | Status | Notes |
|---|---|---|
| Provider order present | Pending |  |
| Clinical note signed | Pending |  |
| Diagnosis supports requested service | Pending |  |
| Required test results attached | Pending |  |
| Payer-specific documentation included | Pending |  |
| Conservative treatment documented if required | Pending |  |
| Patient demographics verified | Pending |  |
| Insurance active | Pending |  |
| Submission method confirmed | Pending |  |
| Case owner assigned | Pending |  |

## Readiness Status Options

- Ready
- Not Ready
- At Risk
- Escalated
- Not Applicable

## Control Rule

Authorization should not be submitted until documentation is either ready or formally marked as documentation risk.

## Operational Signal

If documentation readiness failures repeat, the issue should be reviewed as an upstream workflow defect, not treated as a one-off staff problem.
